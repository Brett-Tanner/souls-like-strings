- Yahoo Japan is a completely separate company from Yahoo US
  - Which obviously means they have different API docs for OIDC...
- ID tokens from an OIDC flow are often delivered as signed JWTs, meaning you need _another_ network request to get the keys to decode them
  - Of course you can cache the keys, but caching is [not exactly known for reducing complexity](/dev/10s_to_100ms.md)
- CHECK IF YOU HAVE A GEM THAT DOES SOMETHING BEFORE WRITING A SUPER DETAILED RFC FOR HOW TO DO THAT THING
  - Also check if there's a more generic gem which can be configured for different IdPs rather than planning to add one for each
- If you have multiple `before_action` with the same names, only the last runs
- Also check if code someone else at your company is writing can be modified to enable what you're doing too...
  - Really just thoroughly research before writing 2 nearly complete RFCs, only to abandon them to write the next
