- One day I'll remember you need `require 'rails_helper'` at the top of RSpec files for it to load any of your application logic
  - Today is not that day
- `JWT.decode` returns an array of `[payload, headers]`, not just the payload as I originally thought
- Uploading a CSV to Gmail can add `\n` between each row for some reason
- Rails always does a warning log if the CSRF token is missing for controllers which use `verify_authenticity_token`
  - Even if it's a JSON request handled by `null_session` and the request proceeds normally
- Another popular mistake of mine: `Secure` cookies are, by definition, only sent over HTTPS
  - So in tests you need the `url` route helper and `protocol: :https`
- Devise's `sign_in` helper won't reset CSRF tokens in tests, since it needs a controller instance to call `reset_csrf_token` on

To mock a HTTP request in RSpec (no other deps)

```ruby
response = Net::HTTPCreated.new('1.1', '200', '') # Or NetHTTPBadRequest, etc.
response.body = { whatever: 'value' }.to_json
response.instance_variable_set('@read', true) # To avoid the read/socket error
```

Also don't call it `response` if you're in a controller spec, or you'll shadow the one that you're probably using in expectations.
