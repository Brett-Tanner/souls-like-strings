- Ruby has both `raise` and `throw`; `throw` should always be used with a `catch` for non-error control flow
  - Also I always use `throw` until someone points it out in review because I've spent too long in JS land
- `dig` does not always work to rescue `hash[:key][:nested_key]` accesses
  - because the value of `:key` can be a string, `dig` works by calling itself recursively and strings don't have a `dig` method
  - so instead you need to rescue `NoMethodError`, which is obviously much clunkier/bulkier than just calling `dig`
- Rebasing to incorporate multiple changes from PR feedback might look cleaner, but it's both annoying to mess up and annoying to review
- Tailing logs via the AWS CLI times out after a while
  - but if you happen to have spun up an ECS container for the task you were running, you can just go look at it in the AWS console
  - We have a lot more users in staging than prod, at least with potentially invalid attributes (> 200 000 vs 68 000)
